## 구현과 검증 기록

이하 항목은 각 작업 커밋에서 변경 내용·검증 결과·남은 문제를 추가한다.

### 공통 계약과 선택적 작업

- State에 제어·품질·추적 필드를 추가하고 공통 모델 팩토리, 근거 수집·인용 검증, 작업 범위·부분 결과 병합을 분리했다.
- 기술 재조사는 요청된 질문만 실행한다. 성숙도·이해관계자·도메인 평가는 요청 기술·항목을 처리하고 다른 결과를 보존한다.
- 도메인 입력 예산을 128KiB로 조정하고 그래프 실행 중 입력·호출 오류를 근거 부족으로 삼키지 않도록 했다.
- 검색 결과 밖 시장 URL은 검증 오류로 복구했다. SQLite 체크포인터 의존성을 잠금 파일에 반영했다.
- 검증: 기존 도메인·시장성·이해관계자 테스트 29개와 신규 범위·병합·근거 충돌 테스트 4개 통과. 전체 그래프 테스트는 구조 변경 단계에서 교체 예정.

### 보고서와 품질 평가

- 보고서 노드의 생성·인용·렌더링 책임을 분리하고 종합·보고서·Judge에 공통 ChatPromptTemplate/구조화 출력 체인을 적용했다.
- 본문은 원래 근거 ID를 유지하며 PDF 저장 시에만 번호 인용으로 바꾼다. 존재하지 않는 ID를 조용히 삭제하지 않는다.
- 구조 검사와 내용 Judge를 결합한 네 항목 품질 평가를 추가했다. 모델 호출 실패·판정 불확실성·품질 미달을 구분한다.
- 최종 PDF는 현재 초안의 통과 판정이 필요하다. 임시 파일의 페이지 수를 확인한 뒤 교체하며, 10쪽 초과·저장 실패 시 기존 파일을 보존한다.
- 검증: 품질 통과·미달, 인용 오류, 오래된 판정 차단, 실제 한글 PDF 생성, 11쪽 PDF의 최종 파일 보존 등 7개 offline 테스트 통과. 실제 LLM 품질 검증은 아직 수행 전이다.

### Supervisor와 지속 가능한 그래프

- 기존 고정 fan-out과 라운드 반복을 제거하고 `supervisor → 선택 노드 → supervisor` 조건부 edge로 연결했다.
- 미완료·변경된 근거·품질 지적에 따라 작업을 배정하며, 외부 호출 오류와 근거 공백을 구분한다. 분야 전체가 비어 있으면 보고서 생성을 허용하지 않는다.
- 노드별 출력 소유권과 Pydantic 타입을 공통 경계에서 검증한다. 원래 근거와 점수를 보존하면서 영향받은 결과만 재검토한다.
- LangGraph SqliteSaver, thread_id, 기본 LangChain trace 전파를 사용한다. 별도 상태 엔진을 만들지 않고 `invoke(None)`으로 재개한다.
- `scripts/run_supervisor.py`에 실행 ID, 중단 지점, 재개 옵션을 제공한다. 제어 필드 타입 중복과 이전 라운드 제어 필드를 정리했다.
- 검증: 전체 offline 테스트 81개 통과. 선택적 재조사, 시장 평가 재사용, 보고서 수정, 오류 분류, 상한 종료, 오래된 품질 판정 차단, SQLite 중단·재개를 포함한다. 테스트의 LLM 응답은 대역이며 PDF 저장은 실제 렌더러로 확인했다.

### 실패 처리 보강과 코드 정리

- 그래프 모드의 PDF·웹 조사와 평가 API 실패를 근거 부족으로 변환하지 않고 실행 경계로 전달한다. 시장성 재작업도 요청된 기준의 검색만 수행한다.
- 잘못된 요청 범위와 잘못된 결과를 구분하고, 평가 필드 누락을 즉시 실패로 처리한다. nullable 실험 조건의 실제 도메인 반환값을 공통 스키마에 맞췄다.
- 공통 모델 팩토리를 도메인 설정에도 연결하고, 수정한 Python 파일 38개의 import·미사용 코드·포맷을 Ruff로 정리했다.
- 검증: 외부 소켓 통신을 차단한 unittest 82개 모두 통과. 변경 Python 파일의 Ruff I/F 검사·포맷 검사와 git diff 공백 검사 통과.
- 실제 PDF 렌더러로 한글 테스트 문서 1쪽을 생성하고 이미지로 열어 글자·장 제목·인용 번호·참고문헌이 겹치지 않는 것을 확인했다. 테스트 원고이므로 실제 기술 평가 보고서로 제출하지 않는다.

### 남은 실행 순서

외부 전송 승인 후 설정된 모델로 새 실행 ID를 사용한다. 기존 완료 PDF를 덮어쓰지 않도록 별도 경로를 지정한다.

```bash
REPORT_PDF_PATH=output/pdf/kv_cache_evaluation_main_ver2.pdf \
  .venv/bin/python scripts/run_supervisor.py --run-id main-ver2-20261007-1
```

종료 상태와 근거 공백·품질 판정·호출 횟수를 확인한다. 중단된 경우 같은 ID에 `--resume`을 사용한다. 실패 원인이 코드이면 해당 원인을 수정·검증한 뒤 새 실행으로 확인한다. `completed`일 때만 최종 PDF 1~10쪽의 내용·인용·레이아웃을 검토하고 LangSmith의 동일 trace_id 실행 화면을 확보한다.

### 실제 실행 재검증 (2026-10-07)

- 사용자가 OpenAI·Tavily·LangSmith 외부 전송과 실제 전체 테스트를 명시적으로 승인했다. 앞의 승인 대기 기록은 당시 상태이며 이후 승인되었다.

- 사용자가 `.env`를 수정한 뒤 실행 `main-ver2-20261007-2`: LangSmith의 403은 재현되지 않았지만 OpenAI 인증 오류가 남았다. 기존 프로세스의 `OPENAI_API_KEY`가 `.env` 값과 달랐고 `load_dotenv(override=False)` 때문에 수정한 파일 값보다 우선했음을 확인했다. 키 원문은 출력하거나 기록하지 않았다.

#### 재실행 최종 결과

- `main-ver2-20261007-3`은 2026-10-07 04:17:20~04:22:02 UTC에 11개 노드 호출 후 `incomplete`로 종료했다. 인증 오류 없이 LangSmith에 모델 호출 61건이 기록됐고 모델 호출 error는 0건이었다. 이는 평가 내용 통과와 별개다.

- 차단 원인: KIVI 도메인 6개 항목 모두 검증된 판단이 남지 않았다. 직접 전송량·지연시간 자료가 부족했고, 메모리·처리량·모델 품질의 모델 응답은 일부 원문 인용을 변경·생략했다. 2.35~3.47배 throughput 범위를 단일 증가율로 제출하거나, 원문 배수를 직접 보고된 백분율로 제출한 것도 검증 기준과 어긋났다. 운영 난이도는 plug-and-play 표현을 거의 무수정 통합 가능으로 확대 해석해 별도 검토에서 탈락했다.
